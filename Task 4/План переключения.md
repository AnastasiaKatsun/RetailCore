## 1\. Цель переключения

Цель переключения — перевести расчёт скидок для всех пользователей с текущего поведения (монолитная логика в core checkout) на новый контур (Promo Service в режиме горячего расчёта). После переключения система должна рассчитывать скидки через Promo Service для 100% трафика, данные о расчётах должны сохраняться в PostgreSQL, а метрики p95 core checkout должны оставаться ≤2.0с, расхождения с теневым режимом — ≤5%. Старый контур (теневой режим) сохраняется как источник сверки и fallback на 72 часа, после чего отключается.

## 2\. Объём переключения

### 2.1. Включаем

* Расчёт скидок через Promo Service (все типы промо: корзина, товар, купоны).
* Запись результатов расчёта (PostgreSQL).
* Алерты по расхождениям между Promo Service и историческими данными теневого режима.
* Feature flag переведён в состояние `enabled` для 100% трафика.

### 2.2. Не включаем

* Сложные промо‑кампании с внешними партнёрами (остаются в монолите).
* Промо с динамическими правилами на основе внешних API (отложены до этапа 3).
* Ручные промо‑акции, управляемые через Admin Tools (обрабатываются отдельно).
* Исторические отчёты за прошлые периоды (не пересчитываются).

### 2.3. Критерии успешного переключения

| Критерий | Целевое значение | Где проверяем | Кто подтверждает |
| --- | --- | --- | --- |
| Доступность Promo Service | ≥99.9% | APM (p95/p99, ошибки 5xx) | SRE Lead |
| Расхождения с теневым режимом (за 24 ч) | ≤5% заказов | Отчёт сверки | QA Lead, Data Analyst |
| p95 core checkout | ≤2.0с | APM, профилирование | Solution Architect |
| Доля ошибок интеграции с Promo Service | ≤0.1% | Логи, дашборд ошибок | Backend Eng |

| Отсутствие дублей записей логов | 0 дублей по `order_id` | SQL‑проверка | Data Analyst |

| Триггер rollback | Порог | Кто принимает решение | Максимальное время реакции |

### 10.2. Шаги rollback

| Шаг | Действие | Ответственный | Проверка результата | Что делать с данными, созданными в новом контуре |
| --- | --- | --- | --- | --- |

| 4 | Сверить и зафиксировать спорные данные (расхождения, дубли) | DBA, Data Analyst | Отчёт расхождений, список спорных записей | Спорные записи помечаются флагом `needs_review` |
| 5 | Сообщить поддержке, бизнесу, команде разработки о rollback | Руководитель переключения | Подтверждение получения сообщений | Инструкции для поддержки обновляются немедленно |

## 13\. Проверка качества cutover‑плана

Перед сдачей проверьте, что:

* Указано, что именно переключается и в каком объёме: расчёт скидок через Promo Service для типовых промо‑кампаний (все пользователи, кроме сложных сценариев с внешними партнёрами).
* Есть go / no‑go условия: стабильность теневого режима, готовность feature flag, консистентность справочников, наличие алертов, готовность инструкций поддержки, согласование коммуникации с бизнесом.
* Роли и ответственность не описаны общими словами, а привязаны к действиям: для каждого шага и проверки указан ответственный (DevOps, SRE Lead, DBA и т.д.) и конкретный результат.
* Сценарий переключения пошаговый и проверяемый: 8 шагов с временными окнами, действиями, проверками и решениями при ошибках.
* Состояние данных до, во время и после переключения описано отдельно: таблицы с источниками истины, подготовкой, проверкой консистентности и действиями при расхождениях.
* Есть наблюдаемость: метрики (p95, ошибки, очереди), дашборды (Grafana, APM), алерты (пороговые значения), владельцы (SRE Lead, QA Lead и др.).
* Новый контур сравнивается со старым через конкретные сценарии и пороги: parallel run и сверка с теневым режимом, допустимое расхождение ≤5%, отдельные проверки для корзины, купонов и отображения скидок.
* Rollback включает код, маршрутизацию, данные, очереди, статусы и коммуникацию: 5 шагов с действиями, проверками и правилами обработки данных, созданных в новом контуре.
* Есть критерии стабилизации после переключения: по периодам (15 минут, 1 час, 1 день, 1 неделя) и метрикам (доступность, расхождения, p95, эскалации).
* По итогам cutover можно принять решение о продолжении roadmap: таблица с чёткими вопросами и ответами, включая условия перехода к следующему этапу.
